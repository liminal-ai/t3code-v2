# Merge brief: liminal-ai/t3code-v2

- Gate: `~/.agents/skills/poteto-mode/scripts/merge-gate/merge-gate --repo liminal-ai/t3code-v2 --pr <n> --method merge`. Merge commits only. Never squash, rebase or run `gh pr merge` (FORK.md, "Branches and merges").
- Codex must have reviewed the current head, with no review thread open. After a push, comment `@codex review` and wait until its summary names the new head. The gate reads `code_review.commit_sha` and `code_review.status` from the `<!-- codex-review-state:v1 {...} -->` line of that comment (`gh api repos/liminal-ai/t3code-v2/issues/<n>/comments`), and the comment's `updated_at` shows when the bot last moved. A review stuck `running` while the bot finishes other PRs can be waived with `--waive codex=<reason>` naming the independent verdict ([#45](https://github.com/liminal-ai/t3code-v2/pull/45)). Codex caught a regression on the 3766 sync that three verifier rounds missed.
- A verdict drives the PR's head through `.agents/skills/verify-t3code/` on a dev server, by path:
  - `apps/server/src/threadWorkflow/`, `apps/server/src/mcp/toolkits/threadWorkflow/` or `apps/web/src/threadWorkflow/`: `features/workflow-tab.md`, with its outcome check.
  - `packages/provider-cursor/`: one real Cursor turn on a throwaway release, per the skill's "Release check", because a fresh dev server's Cursor is signed out and nobody signs an unattended verifier in ([#45](https://github.com/liminal-ai/t3code-v2/pull/45)'s first verdict).
  - `apps/web/src/groupChat/`, `apps/server/src/groupChat/`, `routes/group-chat*` or `mainAppLocation.ts`: `features/group-chat.md`.
  - `apps/server/src/fork/`: `features/agent-turn.md`, and `features/delegated-requests.md` for `DelegatedRequestTimeout.ts`.
  - `apps/server/src/peer/`, `apps/server/src/cli/environment.ts`, `070_PeerLinks.ts`, `071_PeerLinkFence.ts` or `072_WaitingLinkRequestIndex.ts`: `features/linked-environments.md`.
  - Any other `apps/web/` or `apps/server/` change: the feature file for each flow it touches, and `features/agent-turn.md` at least.
  - Docs only (`docs/`, `*.md`): no drive. Read the changed text against the code it describes.
- The verdict line is `pstack-verdict: <PASS|PASS+NOTES|FAIL> head=<sha> base=<sha> by=<model>`. PASS+NOTES passes ([#46](https://github.com/liminal-ai/t3code-v2/pull/46)). Each lane it carries from an earlier verdict is a `shortcut <id>:` line, per the skill's "Re-verification". Accept each on the gate run with `--accept-shortcut <id>=<reason>`, or have it rerun ([#49](https://github.com/liminal-ai/t3code-v2/pull/49), [#50](https://github.com/liminal-ai/t3code-v2/pull/50), [#51](https://github.com/liminal-ai/t3code-v2/pull/51)).
- A PR stacked on another records `base=` as the head of the PR below, so its verdict's hash matches only after that PR lands. Land bottom-up, gating each PR after the one below merges ([#46](https://github.com/liminal-ai/t3code-v2/pull/46) on #45).
- `Agent context budget` fails when a PR raises a value in `apps/server/src/provider/agentContextBudget.json` above `main`'s. A maintainer accepts growth with the `agent-context-increase` label. The failed `opened` run stays on the head, and a rerun fails again, so merge with `--waive checks=<reason>` naming the passing `labeled` run ([#45](https://github.com/liminal-ai/t3code-v2/pull/45)). A PR stacked on one that grows the budget passes with `gh run rerun <id> --failed` once that PR lands ([#46](https://github.com/liminal-ai/t3code-v2/pull/46)).
- Before the push: `vp run check:changed`, never repo-wide checks. An upstream sync instead typechecks each package the fork touches and lints the files that differ from the upstream tag. A branch that merged a sync gets the sync's new dependencies first: `CI=true vp install --frozen-lockfile`, then typecheck.
- A change to a file in FORK.md "Seams to re-check" runs the tests listed there. Run the provider-cursor tests from `packages/provider-cursor`, because four fail from the root.
- CI runs neither the live drive nor a sync's throwaway-release check (FORK.md "Sync from upstream" step 4). Before a cutover question, the release runs one real turn each on Cursor, Claude and Codex, per the skill's "Release check".
- `AGENTS.md` or `CLAUDE.md` text: Lee approves the exact text, and the gate checks the approval comment.
- An upstream sync updates "Last synced" in FORK.md in the same PR.
- A merge changes nothing in prod. Only Lee runs or approves a cutover (FORK.md "Cut over").
